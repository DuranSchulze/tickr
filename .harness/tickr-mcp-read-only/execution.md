### Deviations within approved scope

- **Database location (step 1).** The user put the Neon branch in `.env`, not `.env.local`. `DIRECT_URL` was derived by removing `-pooler.` from the host, as earlier migrations on this repo did. C0 confirmed the host before any write.
- **Login and consent forwarding (step 8).** The plugin's signed query repeats the `ba_param` key, and TanStack Router can re-serialize search params, which would break the signature. `loginPage` and `consentPage` are therefore the server routes `/api/oauth/login` and `/api/oauth/consent`. They forward the raw query as one opaque `oauth` parameter to `/auth` and `/oauth/consent`, and pages send it back as `oauth_query`. `oauthProviderClient()` was not added, since an explicit `oauth_query` makes it redundant. Revision 2's step 8 already planned an `oauth` parameter on `AuthSearch`.
- **Redirect rule (step 8).** After sign-in with an existing consent, the plugin returns the client's registered `redirect_uri`, which is cross-origin. So `safeOAuthRedirect` follows plugin-issued URLs except script-capable schemes, rather than same-origin only. The plugin has already matched the URL against the client's registration.
- **Call limiter table (step 7).** `src/db/schema.ts` documents `rate_limit` as owned by Better Auth and not to be repurposed. The limiter therefore uses `auth_abuse_counters` with scope `mcp`, operation `mcp_call`, and a hashed `client:user` bucket.
- **Consent client lookup (step 8).** The consent page reads the client name directly from `oauth_clients`, rather than through `/oauth2/public-client`. It is the same data, read on the server.
- **Migration generation (step 3).** A probe showed existing drift: `schema.ts` no longer defines `pending_gsheets_syncs` (removed in `f1df75c` without a migration), so any generated migration would `DROP` it. The legacy definition was added back only while generating `0029`, so the migration contains no drop and the snapshot matches the database. **Open decision for the user:** drop `pending_gsheets_syncs` in a separate, reviewed migration, or keep it.

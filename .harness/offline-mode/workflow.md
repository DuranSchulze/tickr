**Risks**

- **R1 — neutral shell (Q2) on TanStack Start SSR.** The client expects dehydrated SSR state. A shell with no user data may need `/app` routes to render client-only (selective SSR, `ssr: false`) or a dedicated shell document. Step 9 is a time-boxed spike with a stop rule. If the only working option changes online first paint noticeably or adds a route, that conflicts with [REQ-9] and **returns to spec**.
- **R2 — real-database dedupe test.** Unit tests mock `#/db`, so the unique-conflict path needs a non-production Postgres. Use a Neon branch, as the MCP work item did. `.env.local` is missing, and production has drift. **No migration touches production in this work item.**
- **R3 — async queue API.** The enqueue sites in `useTimerCore` run inside synchronous optimistic-update flows, so the async change must not delay the optimistic UI.
- **R4 — `@tanstack/*` pinned to `latest`.** Record the resolved versions at Step 0 so selective-SSR behavior is checked against the installed version.

## Compatibility, rollout, recovery

- **Migration safety.**
  - `0030` only adds a nullable column and a unique index; existing rows are `NULL`, so the index never conflicts on them.
  - It is applied to the Neon dev branch during execution.
  - Production apply is a separate, explicitly confirmed step with a Neon restore point. It is not part of this workflow.
  - Old clients that send no id keep working.
- **Queue compatibility.** The legacy `localStorage` queue is migrated on first load of the new client, and the old keys are removed only after the commit. An older client tab still open during a deploy can still enqueue to `localStorage`, and the migration picks those items up on its next run (it runs every launch until the legacy keys are empty).
- **Rollback.**
  - Release A: set `OFFLINE_QUEUE_V2_ENABLED=false`. Captures go online-only, and queued items still replay.
  - Release B: set `OFFLINE_CACHE_ENABLED=false` and bump `CACHE_VERSION`.
  - The column stays in place.
  - Reverting the code is safe because the server ignores a missing id.
- **Data loss guard.** No step deletes queue, needs-review, or draft data except a confirmed Discard, a confirmed logout, or a server-confirmed replay.
- **Out of scope here** (per spec): Android shell code, MDM, iOS, CSP, Sentry offline events, and the fault-injection CI matrix.

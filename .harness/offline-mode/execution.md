### Deviations within approved scope

1. **D1 — migration matches production.** The branch, and so production, already has `client_mutation_id varchar(64)` with the unique index `time_entries_member_mutation_unique (workspace_id, workspace_member_id, client_mutation_id)`, unused (0 of 129,093 rows), from the uncommitted work behind [Q1](context-spec.md#q1). `0030` uses that exact definition with `IF NOT EXISTS` instead of the planned `(workspace_id, client_mutation_id)`. Behavior is the same.
2. **D2 — no destructive SQL.** `drizzle-kit generate` also emitted `DROP TABLE "pending_gsheets_syncs"`. It was removed because that decision is still open in the MCP work item. The 0030 snapshot omits the table, so later generates will not propose the drop again.
3. **D3 — pill in `Navbar` only.** The header appears on every `/app` screen at every width; a copy in the `MobileNav` drawer would duplicate it.
4. **D4 — lease fallback in `localStorage`** (synchronous) instead of IndexedDB `meta`. It is only used where Web Locks are missing, and it was not tested across real tabs.
5. **D5 — neutral shell = `/app` route with `?offline-shell=1`** via a function-valued `ssr`. No route was added and online rendering is unchanged. One shell serves every `/app` page.
6. **D6 — existing service worker bug.** It cached `/_build/`, but assets are served from `/assets/`, so app code was never cached before.
7. **D7 — timesheet window:** own default-view weeks starting within 35 days, standing in for "current and previous pay period" (weekly data, semi-monthly periods).
8. **D8 — stale catalog notice** appears in the offline banner rather than on each picker.
9. **D9 — budget:** the time-tracker route limit went from 150 to 170 KB, recorded in `perf/README.md`.
10. **D10 — e2e runner:** a plain script on the installed `playwright` library rather than `playwright.config.ts` with `@playwright/test`, to avoid adding a dependency. It is not part of `check-all`.
11. **D11 — offline logout and the cookie:** the httpOnly session cookie cannot be cleared from the page. A marker finishes the server sign-out on the next online `/app` load, so a relaunch still requires sign-in.

## Integration points and risks

- **Unreleased commit.** `89bd592` is `HEAD` of `mobile` and the only commit not on `origin/mobile` or `origin/main`. Its notice files are listed below. Everything else in that commit is lint work: `doctor.config.json` and ten component and test files.
  - `src/features/announcements/announcement.md`: sidebar text for `AnnouncementCard`.
  - `src/features/announcements/manifest.json`: the `hosting-security-2026-11-23` entry.
  - `src/features/announcements/types.ts`: the `kind: 'notice'` variant of `ChangelogEntry`. Only `src/routes/app/changelog.tsx` consumes it.
  - `src/routes/app/changelog.tsx`: every hunk serves the notice in `ChangelogRoute`. The hunks cover the `id` anchor, the `Shield` badge, notice layout, `aria-hidden` icons, and `parseISO` dates, so the date isn’t shifted by time zone. The whole file goes with the notice.
- **Release path.** `mobile` → pull request → `staging` → pull request → `main`. App Platform deploys `main` without waiting for checks, so green checks on [.github/workflows/check.yml](../../.github/workflows/check.yml) gate each merge. That workflow runs typecheck, lint, test, build, and `perf:ci`.
- **Local hooks.** `.husky/pre-commit` runs `lint-staged`, and `.husky/commit-msg` runs commitlint. Commit messages must be Conventional Commits.
- **External access.** `gh` is not authenticated in this session, and the GitHub MCP server failed to connect. DigitalOcean dashboard and support access is not available to this session. Steps marked _Operator_ need the user, or access the user grants.
- **Risk: losing the lint work during the split.** Step 1 creates a backup branch first.
- **Risk: shipping more than the notice.** Only the notice commit is pushed until step 4 is merged and verified.
- **Risk: production data.** The REQ-3 timer checks write time entries in a test workspace only.
- **Behavior change.** Changing `announcement.md` changes the `AnnouncementCard` dismissal hash. Users who dismissed the weekly-report card will see the security notice. This is intended.

## Compatibility and recovery

- **Notice.** No schema, API, or dependency change. To undo it, revert the notice commit through the step 4 path. For an urgent fix, roll back in App Platform **Activity**. That rollback touches no database data.
- **Split.** If step 2 or 3 goes wrong, `git reset --hard backup/89bd592-pre-split` restores the original commit. Delete the backup branch only after C1 and C3 pass.
- **Infrastructure.** Step 11 rollback follows the existing recovery procedure. Returning to an affected build needs an approved compensating control.

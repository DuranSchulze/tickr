# Make Trackly a properly installable PWA (Add to Home Screen / Install app)

**Decisions (recommended path):** full installability (manifest + minimal service worker + in-app install UI), installed app opens `/app/time-tracker`, install entry point is the account dropdown menu.

## Phase 1 — Manifest & icons

1. **Delete the orphaned** `public/manifest.json` (nothing references it; avoids future drift).
2. **Rewrite** `public/favicon/site.webmanifest` (the file already linked in `__root.tsx`):
   - `name: "Trackly"`, `short_name: "Trackly"`, `description` from `BRAND.description`
   - `id: "/"`, `scope: "/"`, `start_url: "/app/time-tracker"` (relative paths so it works on all deployed domains: trackly.ph, tickr-nu.vercel.app, time-track.buildvault.live)
   - `display: "standalone"`, no orientation lock
   - `theme_color`: brand teal (exact hex converted from default primary `oklch(0.58 0.12 185)`), `background_color: "#ffffff"`
   - icons: existing `android-chrome-192/512` with `purpose: "any"` **plus** new maskable 192/512 entries with `purpose: "maskable"`
   - `shortcuts`: one or two entries (e.g. "Time tracker" → `/app/time-tracker`)
3. **Generate icons** from the current logo `public/logo-8-26-26.png` (dark mark on transparency):
   - `scripts/generate-pwa-icons.mjs` using `sharp` (add as devDependency; check if it's already in node_modules first)
   - Maskable 192/512 + new `apple-touch-icon.png` (180): logo scaled into the 80% safe zone on a solid teal background, logo inverted to white (matches the app's `dark:invert` logo treatment)

## Phase 2 — Root head meta (`src/routes/__root.tsx`)

- Add `theme-color` meta entries (light + `prefers-color-scheme: dark` variant) — colors the mobile browser/OS chrome
- Add `mobile-web-app-capable` + `apple-mobile-web-app-status-bar-style` meta for iOS standalone behavior
- Manifest link already present — unchanged

## Phase 3 — Service worker + offline page

1. **New `public/sw.js`** (hand-written, no workbox): versioned cache name, `install` precaches `/offline.html`, `activate` purges old caches + `clients.claim`, `fetch` handler does network-first for navigations with the offline page as fallback, cache-first for immutable `/_build/` assets, passthrough otherwise.
2. **New `public/offline.html`**: self-contained styled page (inline CSS, brand teal, "You're offline" + retry button).
3. **Registration**: client-only `useEffect` in `RootDocument` (or tiny component), guarded by `import.meta.env.PROD` so dev is never cached.
4. **`vercel.json`**: add header rule for `/sw.js` → `Cache-Control: no-cache` so SW updates roll out promptly. (Existing CSP is `frame-ancestors`-only, no `script-src` — registration unaffected.)

## Phase 4 — In-app install UI

1. **New hook `src/hooks/usePwaInstall.ts`**: captures `beforeinstallprompt`, exposes `canPrompt` / `promptInstall()` / `isInstalled` (display-mode standalone or `navigator.standalone`) / platform detection (iOS vs other).
2. **New `src/components/shared/InstallAppDialog.tsx`**: shows the native install button when available; on iOS Safari shows step-by-step Share → Add to Home Screen instructions instead.
3. **`src/components/time-tracker/Navbar.tsx`**: "Install app" item (lucide `Smartphone` icon) in the avatar dropdown next to Appearance — rendered only when not already installed. Mirror in `MobileNav.tsx` if it has an equivalent menu list.

## Phase 5 — Verification

- `pnpm build` + the repo's check/lint commands (match `.github/workflows/check.yml`)
- Dev server: manifest served & parsed (icons/maskable recognized), `sw.js` registered, offline simulation serves the offline page
- Verify auth-gated `start_url`: signed-out visit to `/app/time-tracker` redirects to sign-in
- Run the react-doctor skill (`/doctor`) as final regression pass

## Notes / risks

- Static `theme-color` meta can only follow the system color scheme, not the in-app manual theme override — acceptable; manifest `theme_color` uses the default teal preset.
- The 15KB `favicon.ico` referenced by the orphaned manifest goes away with the cleanup; the favicon links in `__root.tsx` are untouched.
- Full offline data entry (queued timer entries) is explicitly out of scope.
